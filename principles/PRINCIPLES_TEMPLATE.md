# 原则库模板（PRINCIPLES_TEMPLATE）

> 原则库是整套架构的灵魂：它是 agent 的 constitution，已认同的常识沉淀进机器，
> 机器按原则自动执行，人不再每次口头重复。
>
> **照搬别人的原则等于用别人的宪法。** 复制这份模板，填进你自己的答案。

## 如何使用

1. 逐条阅读下面 8 条通用原则，保留认同的，改写不认同的，删除不适用的。
2. 把 `[填空]` 处换成你自己的具体数字、标准、清单。
3. 组织模式默认 `OPC`；如为公司/集团，重写第 3、4、7 条。

---

### 1. 只认有成本的证据

预售、付费、真实支出才是信号；问卷、点赞、口头认可权重为零。
无成本表态不是信号，有成本的掏钱行为才是信号。

### 2. 唯一硬验证标准

有没有人真正付钱、持续付钱。

- 70% 确定性收入（服务/集成）
- 20% 增长实验（SaaS/Agent）
- 10% 期权（内容/新方向）
\> 我的组合：`[填空]`

### 4. 赚钱路径

卖时间、产品化服务、订阅制小产品、内容杠杆、佣金/授权；
早期 90% 靠卖时间吃饭，先活下来再谈复利。
\> 我的主路径：`[填空]`

### 5. 机器设计师思维

自己当机器的设计师：原则 → 规则 → 可重复流程；
极度求真、按可信度加权；痛苦 + 反思 = 进步（决策留档、定期回测）。

### 6. 浅钻代替回测

无历史数据时，不用昂贵调研，用低成本探针代替回测：
两周 MVP / 预售测试 / 付费意愿访谈。没出金就换地方，不恋战。

## 元原则：机器验证机器

机器用"有没有人付钱"验证机会，人用"有没有赚到钱"验证机器。
在实战赚到钱之前，整套框架只是假设。
