# Prospecting OS · 找矿系统（方法论开源版）

一套**有立场的简易 Agent 架构** + **OPC（单人公司）机会探矿方法论**。

> 定位：先验证需求与现金流，再谈愿景。唯一硬验证标准：有没有人真正付钱、持续付钱。

## 这是什么

找矿系统（Prospecting OS）把"找机会"这件事做成一台机器，而不是靠直觉和运气：

```
公开信号扫描 → 信号看板（打分分级） → 深挖证据 → 浅钻验证（低成本探针） → 矿区档案（开采/观察/坟场） → 定期回测
```

它不是通用 Agent 框架。通用框架无立场，什么都能搭；这套架构**有立场**——
原则库里写死了"只认有成本的证据""付钱是唯一标准"，天生为机会发现调教。
好用的原因正是它只干这一件事。

## 架构：领域 Agent 框架

| 组件 | 角色 | 说明 |
|---|---|---|
| Workers（研究代理/深挖代理） | 干活 | 出去找证据、定向深挖，不做决策 |
| Hermes（路由/信使层） | 流转 | 扫描→信号→深挖→浅钻→档案，任务与结果在各阶段之间流转 |
| 原则库（constitution） | 立规矩 | 给 agent 的 system prompt，不用每次口头重复已认同的常识 |
| 思维模型格栅 | 推理工具箱 | 按触发场景调用，而非常驻说教 |
| 矿脉分 | eval | 信号评分：证据强度 / 离钱近度 / 可切入度 |
| 矿区档案 + 定期回测 | verifier + trace | 决策留档，从错误里提炼原则 |

**复用公式**：新领域 = 换一套原则库 + 换一套信号定义 + 复用架构。找矿系统是第一个实例。

**组织模式**：资源适配度是可配置维度。默认 `OPC 模式`（1 人 + 1 AI），架构支持扩展出公司模式、集团模式等——不同组织形态，可承载的机会集合完全不同。

## 使用方式

1. 读 `FRAMEWORK.md`，理解"有立场的机器"这个核心设计选择。
2. 读 `SPEC.md`，看信号看板 → 浅钻验证 → 矿区档案的完整闭环。
3. 复制 `principles/PRINCIPLES_TEMPLATE.md`，填进你自己的验证标准、组织模式、死亡清单——
   原则库是整套架构的灵魂，照搬别人的原则等于用别人的宪法。
4. 按 SPEC 自己实现，或等可运行代码版本开源。

## 方法论摘要

- **找矿六标志**：钱的流向、痛点浓度、供给断层、成本拐点、人才流向、开源热度
- **只认有成本的证据**：预售、付费、真实支出才是信号；问卷、点赞、口头认可权重为零
- **浅钻代替回测**：无历史数据时，用两周 MVP / 预售测试等低成本探针先验证，再下重注
- **反脆弱组合**（OPC 默认）：70% 确定性收入 + 20% 增长实验 + 10% 期权
- **机器验证机器**：机器用"有没有人付钱"验证机会，人用"有没有赚到钱"验证机器
